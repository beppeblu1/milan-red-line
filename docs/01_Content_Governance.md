# Content Governance v1.0

## Purpose

Milan Red Line is not a collection of independent travel guides.

It is a **Knowledge Network** designed to answer travellers' questions through a structured ecosystem of interconnected content.

The objective of the project is not to publish the highest possible number of articles, but to build and maintain a coherent, scalable and trustworthy editorial system.

---

# Core Principles

## 1. The Network is the Product

The individual guide is not the product.

The product is the **Knowledge Network** created by all guides working together.

Every new guide should improve at least one of the following:

- coverage of the topic;

- quality of the cluster;

- navigation through the network;

- overall usefulness for readers.

Publishing a guide that only improves itself is not sufficient.

---

## 2. Every Guide Owns One Question

Each guide exists to answer **one primary search intent**.

Examples:

| Guide | Primary Question |

|--------|------------------|

| Arriving in Milan | How do I get oriented when I arrive in Milan? |

| How to Use Milan Public Transport | How does Milan's public transport system work? |

| Milan Public Transport Tickets | Which ticket should I buy? |

| How to Use the Milan Metro | How do I use the Milan Metro? |

A guide should never attempt to fully answer another guide's primary question.

---

## 3. Knowledge Ownership

Each important topic has one editorial owner.

Examples:

- Metro → *How to Use the Milan Metro*

- Tickets → *Milan Public Transport Tickets*

- Airports → Airport Specialist Guides

- Local Knowledge → Dedicated Local Guides

Hub and Connector guides introduce topics.

Specialist guides explain them completely.

This prevents unnecessary duplication across the project.

---

## 4. Progressive Specialisation

Whenever a new Specialist Guide is published:

- Hub guides become more concise.

- Connector guides become more concise.

- Detailed explanations move into the new Specialist Guide.

The network should become cleaner as it grows.

Never the opposite.

---

## 5. Links Replace Repetition

Information already explained elsewhere should not be rewritten.

It should be linked.

Internal links are editorial navigation tools before they are SEO tools.

Their purpose is to guide readers naturally towards the next question they are likely to have.

---

## 6. Editorial Debt

Content can accumulate technical debt just like software.

After publishing a new guide, always verify whether:

- duplicated explanations exist;

- better internal links can be added;

- sections can be simplified;

- FAQs still provide unique value;

- outdated references should be removed.

Reducing Editorial Debt is part of the publishing workflow.

---

## 7. Cluster First

Editorial priorities are determined by clusters rather than isolated ideas.

Before opening a new pillar, existing strategic clusters should reach a mature state.

A cluster is considered mature when:

- search intents are clearly separated;

- internal linking is complete;

- unnecessary duplication has been removed;

- Compression Pass has been completed;

- Reading Experience standards are fully respected.

---

## 8. Data Refines Strategy

Google Search Console, Google Analytics 4 and Microsoft Clarity are optimisation tools.

They help answer questions such as:

- Which guides deserve expansion?

- Which sections can be simplified?

- Which queries deserve dedicated content?

- Which internal links should be improved?

Data refines the Knowledge Network.

It does not replace editorial strategy.

---

## 9. Stable Before Bigger

Growth should always be sustainable.

Publishing additional content must never reduce the quality of the existing Knowledge Network.

Stability takes priority over expansion.

---

## 10. Knowledge Network Maintenance

The Knowledge Network requires periodic maintenance.

Recommended frequency:

- every five newly published guides;

- after completing a major cluster;

- after significant Search Console or Analytics insights.

Each maintenance sprint should review:

- Compression Pass;

- duplicated concepts;

- internal linking;

- Related Guides;

- emerging search intents;

- editorial consistency;

- obsolete references.

No new content is required during these sprints.

The objective is to improve the existing network.

---

# Decision Framework

Before implementing any editorial change, ask the following question:

> Does this change improve:

>

> 1. the guide?

> 2. the cluster?

> 3. the Knowledge Network?

If the answer is **no** to all three, the change should normally not be implemented.

---

# Long-Term Vision

The long-term objective of Milan Red Line is not to become the largest travel website about Milan.

The objective is to become one of the most coherent and trustworthy editorial resources for travellers visiting Milan, staying in Sesto San Giovanni and exploring Northern Italy by public transport.

Every guide is a component.

Every cluster is a system.

The Knowledge Network is the product.
